单模块六件套 · 依赖与数据流

feature / page / route / session / task / statemachine — 一个游戏模块内部谁持有谁、数据怎么流、测试在哪 mock（以 arena 为范本）

六个文件的职责

  • • feature.go：纯数据，UI 坐标/颜色/OCR 区域，零运行时依赖
  • • page.go：单页读写，Is/Read/Tap 三类，坐标走 feature
  • • route.go：Enter/Leave 导航，唯一可跨模块（借 kingdom）
  • • session.go：运行计数 + store 持久化
  • • task.go：装配 + Run 入口，定义 mock 接口
  • • statemachine.go：handler 表，纯函数，经 ctx 回调

依赖方向（无环）

  • • feature ← page ← route → Task → handlers
  • • session / cfg → Task（注入），handler 经 ctx 读
  • • page → Detector / Executor（接口，不碰具体平台）
  • • 跨模块只能出现在 route（→ common/kingdom）
  • • statemachine.Machine 引擎由框架提供，业务不重写

测试与扩展

  • • mock task.go 的 page/route 私有接口，newTask 注入
  • • session 用内存 store，runWithOptions 短 interval 驱动
  • • 新模块复制 6 文件，先空 feature 后填坐标
  • • session 同时服务任务内计数与调度器 CheckReady
  • • 对照 internal/game/arena/* 逐文件抄结构最稳
