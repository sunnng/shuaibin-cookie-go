# 脚本 UI 框架抽取为顶层 ui 包，应用以描述符接缝

`internal/ui` 泛化为本模块顶层公开包 `ui/`（模块内公开包，非独立模块/仓库）。应用与框架仅以**描述符**接缝：任务描述符（ID/标题/分类/字段列表）、字段描述符、导航条目在启动时经 `ShellOptions` 显式注入，无全局注册表。配置绑定由**字段描述符**（键/类型/默认值/控件形态/读写闭包）单次声明，Seed/Apply/面板渲染皆由其推导，取代「四处同键」。详情页默认按描述符自动渲染，任务可挂自定义 section 逃生门。灵动岛入框架；任务状态经 `StatusSource` 窄接口注入，`internal/status` 留在应用侧。控件 kit 为英文类型安全 API；主题为数据（QQ 蓝默认，可整套替换或覆盖令牌，无运行时切换）；UI 布局与游戏特征共用 1600×900 基准分辨率单次缩放；`Shell` 实例化持有全部 UI 状态，消灭包级可变状态；保持构建标签切分——android 文件只做薄绘制，纯逻辑无标签可测。迁移分三段相位：纯逻辑 → android 绘制 → 应用接线，每段全绿才推进。

## Considered Options

- **独立本地模块（`./ScriptUI/` + replace）/ 独立 Git 仓库**：被否。保持单模块简单；包边界先行，未来需要时再拆，拆时无需改 API。
- **全局 `RegisterTask` 注册 API**：被否。即 CLAUDE.md 明文禁止的 global registry 模式，带初始化顺序与测试隔离问题；描述符注入同等表达力且无全局状态。
- **框架反射读写应用 config 结构体**：被否。路径字符串编译期不检查，重构易断；读写闭包同样单处声明且类型安全。
- **`internal/status` 整体入框架**：被否。会导致游戏任务代码 import UI 框架包，依赖方向倒置；窄接口注入保持 应用→框架 单向。
- **分类（日常/活动/维护）固化为框架枚举**：被否。游戏运营语义不入框架；分类为任务描述符上的自由字符串，chips 自动推导。导航结构亦全描述符化，但框架提供可复用的任务列表页组件供应用挂载，避免每应用重造列表栅格。
- **Backend 接口 / 自绘命令层**：被否。真实 imgui 后端只存在于插件 NDK 工具链，本地不可验的间接层无回报；以纯逻辑覆盖率补偿绘制层不可验。

## Consequences

- 新增配置项 = 一处字段声明；新增任务 = 一处任务描述符（+ 可选自定义 section）。
- 框架不得 import 应用包；应用代码不直接 import imgui（自定义 section 经框架控件 kit 绘制）。
- 迁移期间 `internal/ui` 与 `ui/` 并存，同文件引用时需 import 别名区分。
- 依赖方向、术语遵守 CONTEXT.md 新增条目（脚本 UI 框架 / 描述符 / 字段 / 主题）。
